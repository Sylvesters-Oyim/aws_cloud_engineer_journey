By the end of today you can Design and build, without copying a recipe, a network with a public web tier and a private tier, endpoints to S3 without internet, and tear it all down cleanly. This is your first portfolio-worthy project.

1. The brief

You are the cloud engineer for a small shop. The client wants a web page that the world can see, an internal "app" server nobody outside can touch, and a file bucket the app can use without sending traffic over the public internet. Budget: near zero.

2. Requirements (the checklist you build against)

  1. New VPC project-vpc 10.20.0.0/16; one public and one private subnet. (Stretch: a second AZ for both.)
  2. Web server in the public subnet serving a page you made, reachable on HTTP from anywhere, SSH only from your IP.
  3. App server in the private subnet, no public IP, reachable on 8080 only from web-sg. Admin via Session Manager (no SSH port open).
  4. S3 bucket (private, encrypted). Add a Gateway VPC endpoint for S3 on the private route table. Prove the app server can aws s3 ls with no NAT.
  5. Everything tagged Project=week2 so you can find and delete it.

3. Hints (only if stuck, in this order)

Hint 1: the build orderVPC → subnets → IGW → route tables → security groups → instances → endpoint → test.
Hint 2: private instance needs an IAM roleCreate an EC2 role with AmazonSSMManagedInstanceCore (Session Manager) and a small S3 read policy on your bucket. Attach it as an instance profile. Never put access keys on the instance.
Hint 3: Session Manager from a private subnet with no NATIt needs three Interface endpoints (ssm, ssmmessages, ec2messages), which cost money per hour. Cheaper for this lab: temporarily use EC2 Instance Connect Endpoint, or SSH via the web server as a jump host with ssh -J and then delete it. State which you used in your notes.
Hint 4: the S3 endpoint testIn VPC → Endpoints → Create → com.amazonaws.REGION.s3 type Gateway → select private-rt. Then on the app server: aws s3 ls. Remove the endpoint and watch it hang: that proves the path.

  1. Create labs/week2-two-tier/README.md in the repo: goal, diagram (redraw the picture above by hand or in draw.io), the CIDRs, the security group rules table, and what you'd improve (multi-AZ, ALB, HTTPS).

5. Teardown order (dependency order matters)

  1. Terminate instances → 2. Delete the S3 endpoint → 3. Empty and delete the bucket → 4. Delete route table associations and custom route tables → 5. Detach and delete the IGW → 6. Delete subnets → 7. Delete security groups → 8. Delete the VPC.
  2. Use Billing → Bills and Cost Explorer tomorrow to confirm there is nothing running. Tag Editor with Project=week2 finds stragglers.
