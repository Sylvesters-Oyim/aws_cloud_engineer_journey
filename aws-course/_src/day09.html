By the end of today you can Hide a server in a private subnet, reach it safely through a jump host, explain how NAT lets private servers go out without letting the internet in, and tell Security Groups from Network ACLs (a favourite exam question).

1. First principles: least exposure

A database or app server rarely needs to be reachable from the whole internet. The safest server is one the internet cannot even route to. But that server still needs to download patches. The pattern: private subnet (no inbound from internet) + NAT gateway (outbound only).

Analogy: staff-only office floor Visitors (internet) can reach the reception (public subnet). The back office (private subnet) has no street entrance. Staff there need to order supplies, so they hand requests to the mail room (NAT gateway) which sends them out under the company's address and passes replies back in. Strangers can't use the mail room to walk in.
NAT gateway costs moneyIt bills per hour (~USD 0.045 in many Regions) plus per GB processed, plus its Elastic IP. Left running a month it's ~USD 32+. Create it only for the experiment and delete it the same hour. Alternatives: a NAT instance (cheaper, self-managed), or VPC endpoints (below), which often remove the need for NAT.

2. Security Group vs Network ACL

Security GroupNetwork ACL (NACL)
AnalogyBodyguard at your doorBorder control at the street entrance
LevelInstance (network interface)Subnet
StateStateful: replies auto-allowedStateless: allow both directions yourself
RulesAllow onlyAllow and Deny, numbered, lowest first
DefaultInbound denied, outbound allowedDefault NACL allows all
Use forNormal day-to-day access rulesBlocking a specific bad IP range

Neat trick: a security group can reference another security group as its source (e.g. "DB accepts port 3306 only from the App SG"). No IP lists to maintain.

3. Lab: bastion + private server (75 min)

  1. In day8-vpc, create a private route table day9-private-rt and associate it with day8-private-b (no IGW route, so it stays private).
  2. Create two security groups in the VPC: bastion-sg (SSH from My IP) and app-sg (SSH source = bastion-sg, not an IP).
  3. Launch bastion in day8-public-a (public IP, bastion-sg) and app in day8-private-b (disable public IP, app-sg). Use one key pair for both.
  4. From your terminal, hop through the bastion with agent forwarding (the key never leaves your laptop): 
    ssh-add ~/.ssh/day9.pem
ssh -A ec2-user@BASTION_PUBLIC_IP
# now on the bastion:
ssh ec2-user@APP_PRIVATE_IP      # works: SG allows bastion-sg
ping -c2 8.8.8.8                 # fails/hangs: no route out yet
  5. Give it outbound access (do this quickly): create a NAT gateway in day8-public-a with a new Elastic IP. Add 0.0.0.0/0 → nat-xxxx to day9-private-rt. Retest on the app server: curl -I https://aws.amazon.com now works. Try reaching it from the internet: still impossible.
  6. Cleanup NOW: delete the NAT gateway, wait for "Deleted", then release the Elastic IP. Terminate both instances. Check VPC → NAT gateways and Elastic IPs are empty.

4. Exam notes

Remember
  • NAT gateway lives in a public subnet, needs an Elastic IP, and is zonal. For high availability use one per AZ.
  • NAT = outbound only. IPv6 equivalent: egress-only internet gateway.
  • Security group = stateful, allow-only. NACL = stateless, allow + deny.
  • S3/DynamoDB from private subnets cheaply: Gateway endpoint.
  • Peering is non-transitive. Many VPCs? Use Transit Gateway.

5. Quiz

Q1. Private instances must download OS patches but must not be reachable from the internet. Solution?NAT gateway in a public subnet, with the private route table sending 0.0.0.0/0 to it.
Q2. You must block one malicious IP address range from a whole subnet. Which tool?A Network ACL deny rule (security groups can't deny).
Q3. Why must a NACL have rules for both inbound and outbound?It is stateless; return traffic isn't automatically allowed.
Q4. Cheapest private path from a private subnet to S3?A gateway VPC endpoint for S3 (free, no NAT charges).
Q5. VPC A peers with B, B peers with C. Can A reach C?No. Peering is not transitive.
