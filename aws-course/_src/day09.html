By the end of today you can Build a VPC from scratch (subnet, internet gateway, route table), launch a web server into it, and explain exactly how a packet gets from your browser to your server. Also: know when you need a NAT gateway and why it costs money.

1. First principles: how does traffic find its way?

A packet leaving your server only asks one question: "Is the destination inside my VPC, or outside?" The route table answers. Each row says "for destinations matching this CIDR, send to that target".

Destination     Target
10.0.0.0/16     local        <- inside the VPC, deliver directly (automatic)
0.0.0.0/0       igw-0abc123  <- everything else goes out the internet gateway

0.0.0.0/0 means "any address". The most specific matching row wins. Without the second row, your subnet is private: it can talk inside the VPC only.

Analogy: the estate gateThe internet gateway (IGW) is the main gate of the estate. It is free, highly available and scales itself. A route table row 0.0.0.0/0 → IGW is the signpost "Exit this way". A server also needs a public IP, otherwise outsiders don't know its house number (the IGW translates between the public and private address).

Public vs private subnet

Public subnetPrivate subnet
Route to IGWYesNo
Typical residentsLoad balancers, bastion hosts, web serversDatabases, app servers
Reachable from internetIf it has a public IP + firewall allowsNever directly
Outbound internet (updates)Via IGWVia NAT gateway in a public subnet

NAT gateway: lets private servers call out (download patches) but blocks anyone calling in. Like a company switchboard that places outgoing calls for staff but never forwards strangers' calls. It's billed per hour plus per GB (roughly US$30+/month if left on), so it's a top surprise-bill cause.

2. Lab: build your own VPC by hand (60–75 min)

Cost safetySkip NAT today (it costs money). You only need one small EC2 instance, and you'll delete everything at the end.
  1. Create the VPC: VPC → Create VPC → VPC only. Name lab-vpc, IPv4 CIDR 10.0.0.0/16. Create.
  2. Create two subnets: Subnets → Create. VPC = lab-vpc. public-a = 10.0.1.0/24 in AZ a; private-a = 10.0.2.0/24 in AZ a.
  3. Create an internet gateway: Internet gateways → Create lab-igw → Actions → Attach to VPC → lab-vpc.
  4. Route table for public: Route tables → Create public-rt in lab-vpc. Routes tab → Edit → Add 0.0.0.0/0 → Internet Gateway → lab-igw. Subnet associations tab → associate public-a.
  5. Auto-assign public IP: Subnets → select public-a → Actions → Edit subnet settings → tick Enable auto-assign public IPv4 address.
  6. Launch a web server: EC2 → Launch instance. Amazon Linux 2023, t2.micro/t3.micro (free-tier eligible one). Network settings → Edit → VPC lab-vpc, subnet public-a. Create a security group allowing HTTP 80 from anywhere (we tighten firewalls tomorrow). Advanced → User data: 
    #!/bin/bash
dnf install -y nginx
echo "<h1>Hello from my own VPC (Day 9)</h1>" > /usr/share/nginx/html/index.html
systemctl enable --now nginx
  7. After 1–2 minutes, open http://<public-ip> in your browser. You should see your page. 🎉 (Use http, not https.)
  8. Break it on purpose (best way to learn): delete the 0.0.0.0/0 route in public-rt and refresh. The page stops loading. Put the route back. You've just proven that the route table is the gate.
  9. Optional (if time): also launch a tiny instance in private-a with no public IP. Confirm you cannot reach it from the internet. We use it tomorrow.
  10. Cleanup: terminate instances → detach and delete the IGW → delete subnets → delete route table (public-rt) → delete lab-vpc. (If deleting fails, something is still attached: read the error.)
    Tip: the wizard Create VPC → VPC and more builds all this in one click, but now you know what it creates.

3. Exam notes

Remember
  • Internet gateway: VPC ↔ internet, free, horizontally scaled. One per VPC.
  • NAT gateway: private subnet → internet only. Lives in a public subnet. Costs per hour + per GB. Resides in one AZ (create one per AZ for resilience).
  • Route table, not the subnet's name, decides public vs private.
  • Egress-only internet gateway = the IPv6 version of NAT (outbound only).
  • VPC peering links two VPCs; Transit Gateway links many; VPN/Direct Connect link to on-premises.

4. Quiz

1. A server in a private subnet needs to download OS patches but must not accept inbound internet traffic. Use?A NAT gateway (in a public subnet).
2. What does 0.0.0.0/0 mean?All IPv4 destinations (the default route).
3. Your web server has a public IP but the page times out. First thing to check among route tables?Whether the subnet's route table has 0.0.0.0/0 → igw (and then the security group).
4. Is an internet gateway chargeable?No. NAT gateways are.
5. Which service connects your corporate data center to AWS over a dedicated private line?AWS Direct Connect (Site-to-Site VPN uses the internet, encrypted).
