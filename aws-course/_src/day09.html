By the end of today you can Create a custom VPC with a public and a private subnet, make the public one reachable from the internet, and prove it by serving a web page from an EC2 instance inside it.

1. The plan

Today is almost all hands-on. You will build exactly what Day 8's diagram showed. Cost: zero (no NAT gateway today; a t3.micro/t2.micro instance is covered by free-tier credits, but read your current plan at aws.amazon.com/free).

Analogy: construction orderYou buy the plot (VPC), divide it into rooms (subnets), build the front door (IGW), then put up the corridor signs (routes). Nobody can walk in until the signs point to the door.

2. Lab: the console way

  1. VPC → Create VPC → VPC only. Name lab-vpc, IPv4 CIDR 10.0.0.0/16. Create.
  2. Subnets → Create subnet in lab-vpc: public-a (10.0.1.0/24, AZ a) and private-a (10.0.2.0/24, AZ a). Create both.
  3. Select public-a → Actions → Edit subnet settings → enable auto-assign public IPv4.
  4. Internet gateways → Create lab-igw → Actions → Attach to VPC → lab-vpc.
  5. Route tables → Create public-rt in lab-vpc. Add route 0.0.0.0/0 → lab-igw. Under Subnet associations attach public-a. Leave private-a on the main route table (local only).
  6. EC2 → Launch instance: Amazon Linux, t3.micro (or free-tier eligible). Network settings → Edit: VPC lab-vpc, subnet public-a, auto-assign public IP enabled, new security group allowing HTTP (80) from anywhere and SSH (22) from My IP.
  7. Under Advanced → User data paste: 
    #!/bin/bash
dnf install -y nginx
echo "<h1>Hello from my own VPC</h1>" > /usr/share/nginx/html/index.html
systemctl enable --now nginx
  8. When the instance is running, open http://<public-ip> in your browser. 🎉
  9. Break it on purpose (this is how you learn): remove the 0.0.0.0/0 → IGW route. Refresh the page. It hangs. Add it back. It works. You now understand routing better than most beginners.

3. Same thing in the CLI (read, don't memorise)

VPC=$(aws ec2 create-vpc --cidr-block 10.0.0.0/16 --query Vpc.VpcId --output text)
SUB=$(aws ec2 create-subnet --vpc-id $VPC --cidr-block 10.0.1.0/24 --query Subnet.SubnetId --output text)
IGW=$(aws ec2 create-internet-gateway --query InternetGateway.InternetGatewayId --output text)
aws ec2 attach-internet-gateway --internet-gateway-id $IGW --vpc-id $VPC
RT=$(aws ec2 create-route-table --vpc-id $VPC --query RouteTable.RouteTableId --output text)
aws ec2 create-route --route-table-id $RT --destination-cidr-block 0.0.0.0/0 --gateway-id $IGW
aws ec2 associate-route-table --route-table-id $RT --subnet-id $SUB

Every console click is just an API call. Tomorrow's lesson about automation (Infrastructure as Code) starts from this idea.

4. Troubleshooting ladder (use this for life)

SymptomCheck, in order
Page times out1) Public IP present? 2) Subnet route to IGW? 3) IGW attached? 4) Security group allows port 80? 5) Network ACL allows it? 6) Is nginx actually running?
SSH refused/timeoutSecurity group source = your current IP? Key file permissions chmod 400?
Page loads from instance but not browserAlmost always a route or security group problem, not the app.

5. Cleanup

Terminate the instance. Then delete in this order (dependencies!): route table public-rt (disassociate first), detach and delete the IGW, delete subnets, delete the VPC. Or: delete the VPC and the console offers to remove attached pieces. Keep your notes; tomorrow you rebuild faster.

6. Quiz

1. You attached an IGW but the instance is unreachable. Name two other things to check.Route table entry to the IGW, public IP on the instance, security group rule.
2. What is the "local" route?An automatic route that lets all subnets in the VPC talk to each other. It cannot be deleted.
3. Why delete the instance before the VPC?Network interfaces from instances are still using the subnet; AWS blocks deletion of in-use dependencies.
4. Does an IGW cost money?No, the gateway itself is free (public IPv4 addresses are charged hourly).
