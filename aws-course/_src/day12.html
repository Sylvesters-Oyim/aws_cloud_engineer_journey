By the end of today you can Match any security question to the right AWS service, encrypt data with your own KMS key, and find out who did what in your account with CloudTrail. Security is the heaviest topic (30%) on both exams.

1. First principles: four questions of security

Almost every security service answers one of these. Learn the question, and the service name follows.

QuestionIdeaServices
Who are you / what may you do?Identity & accessIAM, IAM Identity Center, Cognito, MFA
Can anyone read it?Encryption & secretsKMS, ACM, Secrets Manager, Parameter Store, CloudHSM
Can attackers reach it?ProtectionSecurity Groups/NACL, WAF, Shield, Network Firewall
What happened & is something wrong?Detection & auditCloudTrail, CloudWatch, Config, GuardDuty, Inspector, Macie, Security Hub
Analogy: a bank IAM = ID checks and staff badges. KMS = the vault and its keys. Security groups = doors and guards. WAF = the guard who inspects bags for weapons (web attacks). Shield = crowd control against a mob blocking the entrance (DDoS). CloudTrail = CCTV logbook of every action. Config = inventory that notices a window was left open. GuardDuty = the analyst who spots suspicious behaviour.

3. Lab: encrypt with KMS and read your own audit trail (75 min)

Cost safetyA customer-managed KMS key costs USD 1/month (prorated hourly) plus tiny request fees. We will schedule it for deletion at the end (minimum waiting period 7 days; you stop paying once it's scheduled). CloudTrail Event history (last 90 days) is free.
  1. CloudTrail → Event history. Filter Event name = ConsoleLogin. Find your own login: note source IP, time, and whether MFA was used. Then filter Event name = RunInstances to see your Day 5/8 launches. You can answer "who did what" for any API call.
  2. KMS → Create key: Symmetric, Encrypt and decrypt. Alias alias/day12-key. Key administrators and users: your IAM user/role.
  3. Create bucket yourname-day12-secure. Properties → Default encryption → SSE-KMS → choose day12-key.
  4. Upload a text file. Open its properties: it shows the KMS key used. Now use the CLI: 
    echo -n "my secret" > plain.txt
aws kms encrypt --key-id alias/day12-key --plaintext fileb://plain.txt \
  --query CiphertextBlob --output text | base64 -d > secret.bin
aws kms decrypt --ciphertext-blob fileb://secret.bin --query Plaintext --output text | base64 -d
    Output: my secret. Notice you never held the key itself, only asked KMS to use it.
  5. Back in CloudTrail Event history, filter by event source kms.amazonaws.com: your Encrypt/Decrypt calls are logged within minutes.
  6. Break it: in IAM, temporarily remove KMS permissions from your user (or use a role without them) and re-run decrypt: AccessDeniedException. Encryption is only as good as who may use the key.
  7. Browse (read-only) GuardDuty, Security Hub, Config and Trusted Advisor in the console to see what each looks like. Don't enable paid ones unless you want the 30-day trial.
  8. Cleanup: empty & delete the bucket. KMS → select key → Key actions → Schedule key deletion (7 days).

4. Exam notes

Remember
  • Shared Responsibility: AWS secures the cloud (hardware, facilities, hypervisor). You secure what's in it (data, IAM, OS patches, firewall config, encryption choices).
  • Encryption at rest (KMS: S3, EBS, RDS) and in transit (TLS via ACM).
  • CloudTrail = API audit (who). CloudWatch = performance (how). Config = configuration (what changed).
  • WAF = web exploits; Shield = DDoS; GuardDuty = threats; Inspector = vulnerabilities; Macie = PII in S3.
  • Root user: MFA on, no access keys, use only for tasks that require it.
