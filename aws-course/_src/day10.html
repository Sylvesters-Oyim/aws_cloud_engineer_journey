By the end of today you can Choose between security groups and network ACLs, give private servers outbound internet safely with a NAT gateway, and reach AWS services without the internet using VPC endpoints.

1. Two firewalls, two jobs

Analogy: airport securityThe NACL is the guard at the airport gate checking every person entering and leaving the area against a numbered rule list (including a "banned" list). The security group is the bouncer at one specific room, who only keeps a guest list and remembers everyone he let in, so he lets them out again automatically.

Exam tip"Block a specific malicious IP" → NACL (security groups can't deny). "Allow web traffic to instances" → security group. Security groups can reference other security groups as the source (e.g. DB allows port 3306 only from the web-tier group).

2. Private servers need to phone home: NAT gateway

A database in a private subnet must download patches, but it has no public IP and must stay unreachable. A NAT gateway sits in a public subnet; private subnets route 0.0.0.0/0 to it. It forwards outbound requests and returns replies, but never allows new inbound connections from the internet.

Analogy: the company receptionistStaff make outside calls through the front-desk number. Replies come back to the desk and are passed on. Outsiders can't dial a staff member directly.

3. VPC endpoints: skip the internet entirely

Calling S3 from a private instance through NAT works but costs data-processing fees and leaves your network. A VPC endpoint creates a private path to an AWS service.

  • Gateway endpoint: S3 and DynamoDB only, free, added as a route-table entry.
  • Interface endpoint (PrivateLink): most other services, uses an ENI in your subnet, hourly + data cost.

Other connectivity terms the exam likes: VPC peering (connect two VPCs, not transitive), Transit Gateway (hub connecting many VPCs/on-prem), Site-to-Site VPN (encrypted over the internet), Direct Connect (dedicated physical line).

4. Lab: private instance + S3 gateway endpoint (45 min)

Cost safetySkip the NAT gateway if you only want to avoid cost: the gateway endpoint alone proves the idea. If you do create a NAT gateway, delete it and release its Elastic IP within the hour.
  1. In lab-vpc (rebuild from Day 9 if deleted) launch an instance in private-a with no public IP. Attach an IAM role with AmazonS3ReadOnlyAccess.
  2. Connect with Session Manager (EC2 → Connect → Session Manager; needs the role AmazonSSMManagedInstanceCore too and either NAT or SSM interface endpoints). If this is too fiddly, launch a small public instance as a jump host and SSH through it.
  3. VPC → Endpoints → Create: service com.amazonaws.<region>.s3, type Gateway, select the private route table.
  4. From the private instance: aws s3 ls. It works without any internet route.
  5. Check the private route table: a new prefix list → vpce-xxxx route appeared automatically.
  6. Security group experiment: make a security group web-sg and another db-sg whose inbound rule uses web-sg as source. Notice: no IP addresses.
  7. Cleanup: terminate instances, delete endpoint (free but tidy), delete NAT if created, release Elastic IP.

5. Quiz

1. Which firewall is stateless?Network ACL.
2. How do you block one IP address from reaching your subnet?NACL deny rule (security groups have no deny).
3. Private instance needs OS updates from the internet. What do you add?NAT gateway in a public subnet + route from the private subnet.
4. Cheapest private access from a VPC to S3?S3 gateway endpoint (free).
5. Is VPC peering transitive (A↔B, B↔C means A↔C)?No. Use Transit Gateway for hub-and-spoke.
6. Which connection is a dedicated physical line to AWS?Direct Connect.
