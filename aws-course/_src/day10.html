By the end of today you can Explain how a name like shop.example.com becomes an IP address, name the main Route 53 record types and routing policies, and create a private DNS name for your own servers.

1. First principles: computers want numbers, humans want names

Networks route by IP address. Nobody remembers 52.17.4.9, so we use a phone book that maps names to numbers: DNS (Domain Name System). Route 53 is AWS's DNS service (named after TCP/UDP port 53) and it is global, with a 100% availability SLA.

Analogy: the phone book and the receptionist You ask the receptionist (your ISP's resolver) "call Pizza Place". She doesn't know, so she asks the head directory (root), who says "ask the .com office" (TLD), who says "ask Pizza Place's own directory" (authoritative name server, which is Route 53 if you host the zone there). She remembers the answer for a while (caching, controlled by TTL).

3. Routing policies: DNS as a traffic cop

PolicyUse it when…
SimpleOne answer.
WeightedSend 10% of users to a new version (canary release).
LatencySend each user to the Region with the lowest latency.
FailoverPrimary/standby; health check flips traffic if primary dies.
GeolocationRules by user country (language, licensing, law).
MultivalueReturn several healthy IPs (poor man's load balancing).

4. Lab: your own private DNS names (≈ 45 min, about USD 0.50/month, delete after)

You don't need to buy a domain. A private hosted zone works only inside your VPC, which is exactly how real companies name internal servers (db.internal instead of 10.0.11.37).

  1. Make sure lab-vpc has Enable DNS hostnames and Enable DNS resolution ticked (VPC → Actions → Edit VPC settings).
  2. Route 53 → Hosted zones → Create hosted zone: name lab.internal, type Private hosted zone, associate with your Region and lab-vpc.
  3. Launch one instance in lab-public-a (use the Day 8 settings, with nginx user data) and note its private IP.
  4. In the zone: Create record → name web, type A, value = that private IP, TTL 60.
  5. Connect to a second instance in the VPC (or the same one) and test: 
    nslookup web.lab.internal
curl http://web.lab.internal
    You now reach a server by name. Change the record to a different IP and watch the change after 60 seconds.
  6. Optional with a real domain: if you own one, create a public hosted zone, point your registrar's nameservers to the 4 NS values Route 53 gives you, and add an A record to your web instance. DNS changes can take minutes to hours to spread.
  7. Cleanup: delete the record, delete the hosted zone, terminate the instance(s).

5. Exam notes

Remember
  • Route 53 = DNS + domain registration + health checks. Global service.
  • Alias vs CNAME: Alias works at the zone apex and points to AWS resources; CNAME can't be used at the apex.
  • TTL: low = faster changes but more queries; high = cached longer.
  • Failover routing needs a health check. Latency routing = fastest Region, Geolocation = by country.
