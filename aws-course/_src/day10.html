1. First principles: defence in depth

A castle isn't protected by one wall. It has a moat, an outer wall, and a guard at each door. AWS gives you two firewall layers, plus smart ways to log in without leaving a door open.

Analogy: estate securityThe NACL is the estate-gate guard checking a rule list for everyone entering and leaving the compound (subnet). The security group is the bouncer at each individual house (instance), who remembers who you came in with and lets them back out without re-checking.
Security Group (SG)Network ACL (NACL)
ProtectsAn instance (its network interface)A whole subnet
RulesAllow onlyAllow and Deny
StateStateful: reply traffic is automatically allowedStateless: you must allow the reply traffic too (ephemeral ports 1024–65535)
EvaluationAll rules togetherRules in numbered order, first match wins
DefaultDeny all inbound, allow all outboundDefault NACL allows all
Use forDay-to-day control (90% of cases)Subnet-wide blocks, e.g. blocking a bad IP range

The killer feature: security groups can reference each other

Instead of hard-coding IP addresses, a rule can say "allow port 3306 from anything in the web-sg group". Servers can be added, removed or replaced and the rule still works. This is how real 3-tier apps are locked down.

web-sg : inbound 80 from 0.0.0.0/0
db-sg  : inbound 3306 from web-sg   <- NOT from the internet, only from web servers

Logging in without port 22: Systems Manager Session Manager

SSH needs port 22 open and a key file to protect. Session Manager gives you a browser or CLI shell instead, authenticated by IAM, with no inbound ports and every session loggable. It needs: (1) the SSM agent (preinstalled on Amazon Linux 2023), (2) an IAM role with the policy AmazonSSMManagedInstanceCore attached to the instance, and (3) a network path to the SSM service (internet gateway, NAT, or VPC endpoints).

2. Lab: a locked-down two-tier setup (75 min)

Re-create the Day 9 VPC quickly with the wizard: VPC → Create VPC → VPC and more, name lab, 1 AZ, 1 public + 1 private subnet, NAT gateways: None, VPC endpoints: None. (This reuses everything you learned, in one click.)

  1. Create the IAM role: IAM → Roles → Create → AWS service → EC2 → attach AmazonSSMManagedInstanceCore → name lab-ssm-role.
  2. Create security groups in the lab VPC. web-sg: inbound HTTP 80 from 0.0.0.0/0, no SSH rule. app-sg: inbound Custom TCP 8080 with source = web-sg (pick the group from the dropdown).
  3. Launch the web server in the public subnet with web-sg, auto-assign public IP on, IAM instance profile lab-ssm-role, and the same nginx user-data as Day 9.
  4. Launch the private "app" server in the private subnet with app-sg, no public IP. User data (Python is preinstalled, so no internet is needed): 
    #!/bin/bash
mkdir -p /srv/app && echo "secret internal app" > /srv/app/index.html
cd /srv/app && nohup python3 -m http.server 8080 &
  5. Log in with Session Manager: EC2 → select web server → Connect → Session Manager tab → Connect. (If the button is greyed out, wait 2–3 minutes, then confirm the role is attached.) You're in with zero open ports.
  6. From that shell, test the private server (use its private IP from the console): 
    curl http://10.0.x.x:8080          # works: web-sg is allowed by app-sg
curl --max-time 5 http://10.0.x.x:22   # not allowed: times out
  7. Prove the firewall: from your laptop, try to reach the app server — impossible (no public IP, no route, no rule). Then edit app-sg, remove the 8080 rule, rerun the curl from the web server: it now times out. Add it back. You just watched a security group work.
  8. Try a NACL: VPC → Network ACLs → the lab's one → Inbound → Add rule #50: HTTP 80, source your public IP/32, Deny. Reload the web page: blocked, even though the security group allows it. Delete the rule. (Lower rule number wins.)
  9. Cleanup: terminate both instances → delete the VPC (the wizard-built VPC removes its subnets/IGW/route tables for you) → delete the two SGs if they remain.

3. Exam notes

Remember
  • SG = stateful, allow-only, instance level. NACL = stateless, allow+deny, subnet level.
  • To block one specific IP you need a NACL (SGs can't deny).
  • Prefer SG-to-SG references over IP ranges.
  • Session Manager = shell access with IAM auth and audit logs, no SSH keys or open ports.
  • Shared responsibility: the SG rules are your job, the hypervisor is AWS's.
  • Also in scope: AWS Network Firewall (managed deep inspection), Inspector (vulnerability scans), VPC Flow Logs (who talked to whom).

4. Quiz

1. Which firewall is stateless?The network ACL.
2. You need to block a malicious IP address from reaching your whole subnet. Which tool?A NACL deny rule.
3. An instance has no inbound rules in its SG. Can it still download updates (with a route)?Yes. Default outbound is allow all, and replies are allowed (stateful).
4. Safest way to give a developer shell access to a private instance without opening ports?Systems Manager Session Manager.
5. A DB should accept connections only from the web tier. How?DB security group allows the DB port with the source set to the web tier's security group.
6. Which record captures accepted/rejected network traffic for troubleshooting?VPC Flow Logs.
