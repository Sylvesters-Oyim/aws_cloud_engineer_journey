By the end of today you can Trace what happens when you type a web address, read DNS records, and choose the right Route 53 routing policy.

1. First principles: computers need numbers, humans want names

Networks route by IP address (203.0.113.10). People remember names (example.com). DNS (Domain Name System) is the phone book that turns one into the other. Route 53 is AWS's DNS service (53 = the DNS port).

Analogy: asking for directionsYou ask a local (your resolver) for "Mama's Pizza". They don't know, so they ask the city directory (root servers) → the ".com" district office (TLD servers) → Mama's own receptionist (authoritative server, where Route 53 lives) who gives the street address. Your local remembers it for a while (TTL = cache time).

3. Routing policies (exam favourite)

PolicyUse it when…
SimpleOne resource, no logic
WeightedSend 10% to a new version (canary), 90% to old
LatencySend users to the Region with the lowest latency
FailoverPrimary/standby, switch when health check fails
GeolocationBy user's country (laws, language)
GeoproximityBy distance, with adjustable bias
MultivalueReturn up to 8 healthy IPs (poor man's load balancer)

4. Lab: explore DNS, then (optionally) host your own

  1. In CloudShell or your Linux terminal: 
    dig example.com                  # the answer + TTL
dig +trace example.com           # watch root → TLD → authoritative
dig example.com NS               # who is authoritative
dig MX gmail.com +short
nslookup aws.amazon.com
    Write down: what is the TTL? Which name servers answered?
  2. Run dig +short YOUR-EC2-PUBLIC-DNS-NAME for any instance you launch (or use a public AWS name such as s3.eu-west-1.amazonaws.com). Notice AWS already runs DNS for you.
  3. Optional, if you own a domain (or buy a cheap one; Route 53 domains start around USD 12/year): Route 53 → Hosted zones → Create (public, USD 0.50/month). Copy the 4 NS values to your registrar. Add an A record lab.yourdomain.com pointing to an EC2 public IP serving your nginx page. Wait for propagation, then browse to it.
  4. Add a weighted pair (two A records, weights 90/10, different IPs). Run dig lab.yourdomain.com ten times and count the answers.
  5. Cleanup: delete the records and the hosted zone (otherwise USD 0.50/month continues). Terminate the instance.
📸 Evidence: evidence/day10-dig-trace.txt (paste the terminal output; no secrets in it) and, if done, a Route 53 records screenshot

5. Exam notes

Remember
  • Route 53 = DNS + domain registration + health checks.
  • Alias vs CNAME: alias for AWS targets and apex domains, free of charge.
  • Low TTL = changes spread fast but more queries. High TTL = cached longer.
  • DNS only answers "where is it?". It does not carry your traffic or cache your content.
