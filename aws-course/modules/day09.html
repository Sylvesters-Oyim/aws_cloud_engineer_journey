Private Subnets, NAT and Network Security

By the end of today you can Design a public/private two-tier network, explain NAT and VPC endpoints, and tell Security Groups from Network ACLs (a guaranteed exam topic).

1. First principles: not everything should face the internet

Your web server must be reachable. Your database must not. The safest door is the one that doesn't exist. So we split the VPC: public subnets for things that must be reached, private subnets (no route to the IGW) for everything else.

But a private server still needs to go out (OS updates, calling APIs). That is what NAT is for.

Analogy: a company switchboardStaff (private servers) have no public phone numbers. When they call out, the switchboard (NAT gateway) places the call under the company's number and routes the reply back. Outsiders can't ring a staff member directly.

2. Security Group vs Network ACL

Security GroupNetwork ACL
ProtectsAn instance (its network interface)A whole subnet
StateStateful: replies auto-allowedStateless: allow both directions yourself
RulesAllow onlyAllow and Deny, evaluated in number order
DefaultDeny in, allow outDefault NACL allows all
AnalogyThe NACL is the estate guard at the street entrance (can ban a specific car). The security group is the door on each house, with a guest list. A pro move: let the DB's security group allow port 3306 from the web server's security group instead of an IP address.

3. Reaching AWS services privately: VPC endpoints

Normally traffic to S3 leaves via the internet. A gateway endpoint (S3 and DynamoDB only, free) adds a route so traffic stays on AWS's network. An interface endpoint (PrivateLink, most other services) puts a private IP in your subnet and costs per hour.

4. Lab: a private server nobody can reach

Cost safetyA NAT gateway costs about USD 0.045/hour plus data and an Elastic IP. Do the NAT part in one sitting and delete it right after (it's 15 minutes of cost, a few cents). Never leave one overnight.
  1. Reuse your Day 8 VPC (rebuild if you deleted it, it takes 5 minutes now!). Add a subnet day9-private-a, 10.0.2.0/24, same AZ, no public IP.
  2. Create a route table day9-private-rt (only the local route) and associate it with the private subnet.
  3. Launch a web server in the public subnet (security group: SSH from My IP) and a second instance in the private subnet. Its security group allows SSH from the web server's security group only.
  4. SSH into the public one with agent forwarding: ssh -A -i key.pem ec2-user@PUBLIC_IP, then ssh ec2-user@PRIVATE_IP. You hopped through a bastion host.
  5. On the private instance run curl -m 5 https://example.com. It times out: no way out.
  6. Create a NAT gateway in the public subnet with a new Elastic IP. Edit day9-private-rt: 0.0.0.0/0 → NAT gateway. Re-run curl. Now it works.
  7. Cleanup (critical): delete the NAT gateway, wait till "Deleted", release the Elastic IP, terminate both instances, remove the VPC pieces.

5. Exam notes

Remember
  • NAT gateway lives in a public subnet, is managed by AWS, and is AZ-specific.
  • Bastion host = jump server in a public subnet. The modern alternative is Systems Manager Session Manager (no open SSH port).
  • Need to block one bad IP? Use a NACL deny. Security groups can't deny.
  • Private access to S3 for free: gateway endpoint.

6. Quiz

Q1. Which is stateless: security group or NACL?NACL.
Q2. Private instances must download patches. What do you add?A NAT gateway in a public subnet, plus a route from the private subnet.
Q3. Block a malicious IP at subnet level?NACL deny rule.
Q4. Cheapest private path from EC2 to S3?S3 gateway endpoint (free).
Q5. Where must the NAT gateway be placed?In a public subnet.
