1. First principles: you can't protect what you can't see

Security is prevention, detection and response. Day 3 to 12 were prevention. Today is detection. Three different questions, three different services:

3. Lab part A: investigate yourself with CloudTrail (45 min)

  1. CloudTrail → Event history. Filter Event name = ConsoleLogin. Open your login event. Note the source IP, user agent and whether MFA was used.
  2. Do an action: create then delete an S3 bucket. Wait ~5 minutes, filter Event name = CreateBucket and DeleteBucket. Find your event JSON.
  3. Also in the CLI: 
    aws cloudtrail lookup-events --lookup-attributes AttributeKey=EventName,AttributeValue=CreateBucket --max-results 3
  4. Go back to Day 12: find the AccessDenied / Decrypt events (KMS) that your test user caused.
  5. Create a trail to keep history beyond 90 days: CloudTrail → Create trail → all Regions → new S3 bucket. (First trail's management events are free, S3 storage costs pennies.)

4. Lab part B: alarm on a busy server (1 h)

Cost safetyOne t3.micro for under an hour. First 10 alarms are free. Terminate the instance at the end.
  1. Launch an Amazon Linux instance (Day 5 recipe) with detailed monitoring off. SSH in.
  2. CloudWatch → Alarms → Create alarm → Select metric → EC2 → Per-instance → CPUUtilization of your instance. Condition: greater than 50 for 1 datapoint of 5 min. Notification: new SNS topic with your email; confirm the subscription email. Name day13-cpu-high.
  3. Burn CPU: 
    sudo dnf install -y stress-ng
stress-ng --cpu 2 --timeout 600s
  4. Watch the metric graph climb. Within ~5–10 minutes the alarm turns In alarm and an email arrives. 📧
  5. Stop the stress (Ctrl+C) and see it return to OK.
  6. Open Logs → Log groups (empty is fine) and read about the CloudWatch agent: metrics like memory and disk need it, because AWS can't see inside your OS.
  7. Cleanup: delete the alarm and the SNS topic; terminate the instance. Keep the trail (cheap) or delete it.

6. Exam notes

Remember
  • CloudTrail = API activity (governance/audit). CloudWatch = performance/operations. Config = resource state and compliance.
  • Default CloudWatch EC2 metrics don't include memory. Basic = 5 min; detailed = 1 min.
  • Shield Standard is free for everyone; Advanced is a paid add-on with response team.
  • WAF filters HTTP requests; security groups/NACLs filter ports and IPs.
