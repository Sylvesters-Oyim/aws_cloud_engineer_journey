Weekend Project: Two-Tier Network Architecture

By the end of today you can Design and build a realistic two-tier architecture (public web tier, private app tier) across two Availability Zones, document it with a diagram, and explain every design choice, which is exactly what SAA-style exam questions and job interviews ask.

1. The mission

You are the new cloud engineer at a small company. The boss wants a website where the web server is reachable by the public but the app/database server is hidden, and the whole thing must survive the loss of one AZ's subnet. You will build the network skeleton and prove each rule works.

Analogy: a restaurantThe dining room (public subnet) faces the street; the kitchen (private subnet) is behind a staff-only door. Customers talk only to waiters; the kitchen talks only to waiters. Two identical restaurants in different streets (AZs) mean one flood doesn't close the business.

2. Build (3 hours, in 4 blocks)

  1. Network (60 min): VPC 10.0.0.0/16; four /24 subnets as in the diagram; one IGW; public-rt (route to IGW) associated with both public subnets; private subnets on a private route table with no internet route.
  2. Firewalls (30 min): web-sg (HTTP from anywhere, SSH from My IP), app-sg (TCP 8080 from web-sg only, no public source).
  3. Servers (45 min): a web instance in each public subnet (nginx via user data as on Day 9, show the instance's AZ on the page using the metadata service: curl -s http://169.254.169.254/latest/meta-data/placement/availability-zone may need IMDSv2 token headers). One tiny app instance in a private subnet running python3 -m http.server 8080.
  4. Prove it (45 min): fill in this table with evidence:
    TestExpectedResult
    Browser → web server public IP:80Page loads
    Browser → app server private IP:8080Unreachable (no public IP)
    SSH into web server, then curl <app-private-ip>:8080Works
    Remove the app-sg rule → repeat curlTimes out
    Stop web server in AZ a → browse to AZ b serverStill works

3. Stretch goals (if time allows)

  • Put an Application Load Balancer across both public subnets pointing at both web servers (preview of Week 3). ALBs cost about USD 0.0225/hour, so delete after testing.
  • Add a NACL deny rule for your own IP and watch the page become unreachable; then remove it.
  • Enable VPC Flow Logs to CloudWatch for 10 minutes and read a rejected packet.

4. Document it (30 min): your portfolio piece

Create aws-course/labs/week2-two-tier/README.md with: the diagram (export from the console's Resource map or use the SVG above), CIDR table, security group rules, the test table, and three things that went wrong and how you fixed them. Recruiters read this more than any certificate.
