Security Services: Keys, Secrets, Logs and Guards

By the end of today you can Say which AWS security service answers which question, encrypt data with KMS, store a secret properly, and audit who did what with CloudTrail. Security is 30% of the Cloud Practitioner exam, so this day pays off.

1. First principles: five questions of security

Every service below answers one plain question about your house:

QuestionHome analogyAWS service
Who may enter and what may they do?Keys and guest rulesIAM (Day 3)
Is my data unreadable if stolen?A safeKMS (encryption keys), ACM (certificates)
Where do I keep the passwords?A lockbox, not a sticky noteSecrets Manager, SSM Parameter Store
Who did what, when?CCTV recordingsCloudTrail (API calls), CloudWatch (metrics/logs), Config (configuration history)
Is someone attacking or misbehaving?Alarm system and security guardGuardDuty (threat detection), Inspector (vulnerability scans), Macie (finds sensitive data in S3)
Block attacks at the door?Fence and bouncersWAF (web exploits: SQL injection, bots), Shield (DDoS; Standard is free and automatic)

2. Shared responsibility, again

Analogy: renting a flatAWS is the landlord: building, locks on the main door, power (security OF the cloud). You lock your own flat, decide who gets keys, and don't leave valuables in the hallway (security IN the cloud: IAM, data, OS patches on EC2, firewall rules). The more managed the service, the more the landlord handles (S3 and Lambda shift more to AWS than EC2).

3. Lab

Part A: CloudTrail, the CCTV

  1. CloudTrail → Event history (on by default, 90 days, free). Filter Event name = RunInstances or ConsoleLogin. You'll see your own actions from earlier days: user, time, source IP.
  2. Open one event and read the JSON. Find userIdentity and sourceIPAddress. This is how investigations start.
  3. Optional: create a trail that stores logs in S3 for longer than 90 days (first management trail is free; the S3 storage isn't).

Part B: KMS, your own encryption key

  1. KMS → Customer managed keys → Create key: symmetric, encrypt and decrypt, alias lab-key. Customer-managed keys cost ~USD 1/month (prorated), and you'll schedule deletion at the end.
  2. Encrypt a file with the CLI: 
    echo "my secret plan" > plan.txt
aws kms encrypt --key-id alias/lab-key \
  --plaintext fileb://plan.txt --query CiphertextBlob \
  --output text --profile lab | base64 --decode > plan.enc
aws kms decrypt --ciphertext-blob fileb://plan.enc \
  --query Plaintext --output text --profile lab | base64 --decode
    It prints your text back. Anyone without permission on the key cannot decrypt, even if they steal plan.enc.
  3. Show the idea in S3: bucket → Properties → Default encryption → SSE-KMS with lab-key. Every upload is now encrypted with your key, and CloudTrail records every use of it.

Part C: Secrets Manager

  1. Secrets Manager → Store a new secret → Other type → key password value S3cr3t! → name lab/db-password (about USD 0.40/month).
  2. Read it from the CLI: 
    aws secretsmanager get-secret-value --secret-id lab/db-password \
  --query SecretString --output text --profile lab
    Your code fetches the secret at runtime instead of hard-coding it in a file or GitHub repo. Rotation can be automatic for RDS.

Part D: look, don't touch

  1. Open GuardDuty (30-day free trial; enable only if you want) and Trusted Advisor (Basic checks free). Read the finding categories: you'll recognise "exposed access keys" and "open security groups" from earlier days.
  2. Cleanup: KMS → select lab-key → Key actions → Schedule key deletion (minimum 7 days). Delete the secret (it has a recovery window too). Disable GuardDuty if you enabled it. Delete plan.txt and plan.enc locally; never commit them.

4. Exam notes

Remember
  • CloudTrail = who did what (API audit). CloudWatch = how is it performing (metrics, logs, alarms). Config = how did it change.
  • GuardDuty = threat detection from logs. Inspector = software vulnerabilities. Macie = sensitive data in S3. Shield = DDoS. WAF = web app firewall (layer 7).
  • KMS = manage encryption keys. Secrets Manager = rotate and retrieve secrets. Artifact = download AWS compliance reports.
  • Encryption at rest (stored data) vs in transit (TLS/HTTPS).

5. Quiz

Q1. Who deleted that security group last night?CloudTrail.
Q2. Detect compromised instances and unusual API activity automatically?GuardDuty.
Q3. Find PII like names and card numbers in S3?Amazon Macie.
Q4. Block SQL injection against a website?AWS WAF (on CloudFront or ALB).
Q5. Who patches the guest OS of an EC2 instance?The customer.
Q6. Where should an app get its database password?Secrets Manager (or Parameter Store), not source code.
