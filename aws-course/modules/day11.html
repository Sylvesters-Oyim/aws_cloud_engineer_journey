DNS and CDN: Route 53 and CloudFront

By the end of today you can Explain how a domain name becomes an IP address, pick the right Route 53 routing policy, and put a private S3 website behind CloudFront with HTTPS so it loads fast worldwide and is no longer publicly exposed.

1. First principles: names, and distance

Computers use numbers (93.184.216.34); humans use names (example.com). DNS is the phone book that translates one into the other. Route 53 is AWS's DNS service (named for DNS's port, 53). It does three jobs: register domains, host DNS records, and route traffic intelligently (health checks, failover, geography).

Analogy: phone book + traffic copLooking up shop.example.com is like asking directory enquiries for a number. Route 53 is a clever directory: "If the Nairobi shop is closed (health check failed), give out the Cape Town shop's number instead."

2. CloudFront: bring the content to the user

If your S3 bucket is in Ireland, a user in Nairobi waits for light to cross the ocean on every request. CloudFront is a CDN (content delivery network): copies of your files are cached at 400+ edge locations, so most requests are answered from nearby. It also gives you HTTPS, DDoS absorption (with Shield Standard) and lets you keep the bucket private.

Analogy: pizza scooters againThe origin (S3/your server) is the central kitchen. Edge locations are scooters parked in each neighbourhood with popular pizzas ready. First customer in a neighbourhood waits for the kitchen (cache miss); everyone after is served from the scooter (cache hit). TTL is how long the pizza stays warm before being replaced.

3. Lab: private S3 site behind CloudFront (75 min)

Reuse your Day 6 bucket idea, but this time do not turn on public access or static website hosting.

  1. Bucket: S3 → Create bucket yourname-cdn-lab-12345 (globally unique). Keep Block all public access = ON.
  2. Upload an index.html (any page; copy your nginx-lab one) and one image.
  3. CloudFront → Create distribution. Origin domain: pick your bucket (the S3 REST endpoint, not the website one). Origin access: Origin access control settings (recommended) → create new OAC. Default root object: index.html. Security: you can skip WAF for now. Create.
  4. CloudFront shows a banner: "Copy policy" → go update the bucket policy. Open the bucket → Permissions → Bucket policy → paste it → Save. (It grants cloudfront.amazonaws.com read access, conditioned on your distribution.)
  5. Wait until the distribution Status is Deployed (3–10 minutes). Open https://dXXXX.cloudfront.net — your page loads over HTTPS.
  6. Prove it's private: open the direct S3 object URL — you get Access Denied. Only CloudFront can read it.
  7. Watch the cache: 
    curl -sI https://dXXXX.cloudfront.net/index.html | grep -i -E "x-cache|age"
# 1st: X-Cache: Miss from cloudfront     2nd: X-Cache: Hit from cloudfront
  8. Invalidate: edit and re-upload index.html; you may still see the old copy until TTL ends. Create an invalidation for /* to force refresh (first 1,000 paths a month are free).
  9. Route 53 (optional, only if you own a domain): create a hosted zone (US$0.50/month), add an Alias A record to your distribution, and attach a free ACM certificate (must be requested in us-east-1 for CloudFront). Skip this if you have no domain; understand the idea.
  10. Cleanup: Disable then delete the distribution (disabling takes a few minutes), empty and delete the bucket, delete any hosted zone.

4. Exam notes

Remember
  • Route 53 = DNS + health checks + domain registration; 100% availability SLA, global service.
  • Alias records work at the zone apex (root domain) and for AWS resources; CNAMEs cannot.
  • CloudFront = CDN for static and dynamic content; S3 stays private via OAC.
  • Global Accelerator = fixed anycast IPs and AWS backbone for TCP/UDP apps (not caching).
  • Caches reduce latency and origin load; Lambda@Edge / CloudFront Functions run code at the edge.
  • ACM issues free public TLS certificates (CloudFront needs them in us-east-1).

5. Quiz

1. Which Route 53 policy sends 10% of traffic to a new version?Weighted routing.
2. Which service reduces latency for global users by caching content near them?Amazon CloudFront.
3. Need example.com (root) to point to a CloudFront distribution. Record type?Alias (A) record. CNAME can't be used at the apex.
4. How do you let CloudFront read an S3 bucket but nobody else?Origin Access Control plus a bucket policy trusting the distribution.
5. Route to a standby Region if the primary is unhealthy?Failover routing with health checks.
6. What gives you static anycast IPs for a TCP game server?AWS Global Accelerator.
