CloudFront: Make Your Site Fast and Safe Worldwide

By the end of today you can Put a private S3 bucket behind CloudFront so your static website is served over HTTPS from servers near every visitor, and nobody can bypass CloudFront to hit the bucket directly.

1. First principles: distance is slow

Light needs time to travel. A visitor in Nairobi fetching a page from a server in Virginia waits for many round trips across oceans. Fix: keep copies close to users. CloudFront is AWS's CDN (Content Delivery Network) with hundreds of edge locations worldwide that cache your content.

Analogy: a bookstore chain The origin (S3 bucket) is the publisher's warehouse far away. Edge locations are local bookshops. First customer asks for a book: the shop orders it from the warehouse (cache miss), keeps a copy, and every next customer is served from the shelf (cache hit) until the copy is stale (TTL expires).

2. Vocabulary

TermMeaning
DistributionOne CloudFront setup, with its own dxxxx.cloudfront.net domain
OriginWhere the real content lives: S3, ALB, EC2, any HTTP server
TTLHow long edges keep a copy
InvalidationForce edges to drop cached files now (/*). First 1,000 paths/month free
OAC (Origin Access Control)Lets CloudFront, and only CloudFront, read a private bucket. Replaces the older OAI
ACM certificateFree TLS cert for your own domain. For CloudFront it must be requested in us-east-1
Price classLimit which edge regions you use to cut cost

3. Lab: private bucket + CloudFront (75 min)

Cost safetyCost is pennies for light traffic, but delete the distribution afterwards (disable first, wait, then delete). Check the current CloudFront pricing/plan page: AWS has changed plans recently.
  1. Create an S3 bucket yourname-day11-site with Block all public access ON (the opposite of Day 6's public site).
  2. Upload an index.html (reuse your nginx-lab page or write a new one with an image).
  3. CloudFront → Create distribution. Origin domain = your bucket (pick the S3 option, not "website endpoint"). Origin access = Origin access control settings → Create new OAC (defaults).
  4. Set Default root object = index.html. Viewer protocol policy = Redirect HTTP to HTTPS. Skip WAF for now. Create.
  5. CloudFront shows a banner with a bucket policy to copy. Open the bucket → Permissions → Bucket policy → paste → save.
  6. Wait ~3–5 min for "Last modified" to replace "Deploying". Open https://dxxxx.cloudfront.net: your site, over HTTPS.
  7. Prove the lock: try the bucket's own URL: Access Denied. Only CloudFront can read it.
  8. Watch the cache: 
    curl -sI https://dxxxx.cloudfront.net | grep -i x-cache
# first:  x-cache: Miss from cloudfront
# again:  x-cache: Hit from cloudfront
  9. Edit index.html, re-upload, reload: you may still see the old version (cached!). Run Invalidations → Create → /* and reload to see the new one.
  10. Cleanup: disable the distribution, wait until deployed, delete it. Empty and delete the bucket.

4. Exam notes

Remember
  • CloudFront = CDN for static and dynamic content, improves latency and offloads the origin.
  • Keep S3 private; use OAC. Public buckets for websites are a legacy pattern.
  • Edge → CloudFront. Don't confuse with Global Accelerator (routes TCP/UDP over the AWS backbone to a fixed anycast IP, no caching).
  • CloudFront integrates with WAF (block attacks) and Shield (DDoS), and supports geo-restriction.
  • S3 Transfer Acceleration speeds uploads to a bucket over long distances.

5. Quiz

Q1. Users worldwide complain a static site is slow. Fix with least effort?Put CloudFront in front of the S3 origin.
Q2. How do you allow only CloudFront to read a bucket?Origin Access Control + a bucket policy that trusts the distribution.
Q3. You updated a file but visitors still see the old one. What now?Create an invalidation (or wait for TTL / use versioned file names).
Q4. Which service gives static anycast IPs and non-cached global routing?AWS Global Accelerator.
