CloudFront: Fast and Secure Delivery

By the end of today you can Explain what a CDN does, put CloudFront in front of a private S3 bucket, and serve your site over HTTPS from edge locations worldwide.

1. First principles: distance is delay

Data moves near the speed of light, but a round trip from Nairobi to Virginia still costs ~200 ms, and a page needs many round trips. If the content already sits near the user, the delay disappears. A CDN (Content Delivery Network) keeps copies of your content in many places. CloudFront is AWS's CDN with 400+ edge locations.

Analogy: pizza scooters againThe origin (S3 or your server) is the central kitchen. Edge locations are scooters parked in every neighbourhood with popular pizzas. First customer in a street: the scooter fetches from the kitchen (cache miss). Everyone after: instant (cache hit). TTL = how long a pizza stays "fresh".

2. The vocabulary

TermMeaning
DistributionYour CloudFront setup; gets a domain like d111abcd.cloudfront.net
OriginWhere the original content lives: S3, ALB, EC2, any HTTP server
BehaviorRules per URL path (e.g. /api/* not cached)
OAC (Origin Access Control)Lets CloudFront read a private bucket, nobody else can
InvalidationForce edges to drop cached files (/*)
ACM certificateFree TLS certificate for HTTPS on your own domain (for CloudFront, create it in us-east-1)

Benefits: lower latency, offload the origin, built-in DDoS protection (Shield Standard), HTTPS, and cheaper data transfer out than direct from S3.

3. Lab: HTTPS static site on a private bucket

Cost safetyCloudFront has a generous monthly free allowance and S3 pennies for a tiny site. Still, disable then delete the distribution at the end (takes a few minutes to deploy and to disable).
  1. Create an S3 bucket day11-site-YOURNAME-123, Block all public access ON (as Day 6, the opposite of last time).
  2. Upload an index.html (reuse your nginx-lab page, add a funny line and an image).
  3. CloudFront → Create distribution → origin = your bucket (choose the S3 REST endpoint, not the website endpoint). Origin access: Origin access control (OAC) → create new. Default root object: index.html. WAF: skip (costs).
  4. After creating, CloudFront shows a banner: Copy policy → go to the bucket → Permissions → Bucket policy → paste → save. (This lets only this distribution read the bucket.)
  5. Wait until status says Deployed (~3–5 min). Open https://dXXXX.cloudfront.net. 🎉 HTTPS, no server, no public bucket.
  6. Prove the bucket is private: open the S3 object URL directly. You get AccessDenied.
  7. Test caching: curl -sI https://dXXXX.cloudfront.net | grep -i x-cache. First time Miss from cloudfront, second Hit from cloudfront.
  8. Edit your index.html, re-upload, reload: you may still see the old one (cached!). Create an invalidation for /* and it updates.
  9. Cleanup: Disable the distribution → wait → Delete. Empty and delete the bucket.

4. Exam notes

Remember
  • CloudFront caches at edge locations; Global Accelerator is different (routes TCP/UDP over AWS backbone to your endpoints, no caching).
  • Private S3 + CloudFront = use OAC (the older name was OAI).
  • Signed URLs/cookies restrict content to paying/authorised users.
  • Geo-restriction can allow/block countries.

5. Quiz

Q1. Users worldwide complain a static site is slow. Fix?Put CloudFront in front of the origin.
Q2. Keep an S3 bucket private but let only CloudFront read it?Origin Access Control with a bucket policy.
Q3. You updated a file but users see the old one?It's cached; create an invalidation or version the file name.
Q4. Where is the certificate for CloudFront requested?ACM in us-east-1.
Q5. CloudFront vs S3 Transfer Acceleration?CloudFront caches downloads for many users; Transfer Acceleration speeds up uploads to S3 over edge locations.
