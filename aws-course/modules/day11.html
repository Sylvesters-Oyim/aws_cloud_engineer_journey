Route 53 and CloudFront

By the end of today you can Explain how a name like example.com becomes an IP address, pick a Route 53 routing policy, and put CloudFront in front of an S3 site so it loads fast and over HTTPS worldwide.

1. First principles: computers talk in numbers, humans in names

DNS (Domain Name System) translates names into IP addresses. Amazon Route 53 is AWS's DNS service (the name comes from DNS using port 53). It does three jobs: register domains, host DNS records, and health-check endpoints to steer traffic.

Analogy: the phone bookYou remember "Mama", not her number. The contacts app looks it up. Route 53 is a global contacts app for the internet, with the extra trick of giving you a different number depending on rules (nearest, healthiest, or split 90/10).

3. CloudFront: a CDN

If your server is in Ireland, a user in Nairobi waits for light to cross the planet on every request. CloudFront caches copies of your content at edge locations (Day 4) close to users. First request: edge fetches from the origin (S3, ALB, EC2). Next requests: served instantly from the edge.

Analogy: neighbourhood kiosksInstead of every customer travelling to the factory, kiosks stock popular items. Only when a kiosk runs out does it call the factory.

Origin Access Control (OAC) keeps your S3 bucket private so that only CloudFront can read it. Never make the bucket public for this.

4. Lab: private S3 site behind CloudFront (60 min)

  1. Create an S3 bucket (block all public access stays ON). Upload an index.html, e.g. your nginx-lab/html/index.html.
  2. CloudFront → Create distribution. Origin: your bucket (choose the S3 REST endpoint, not the website endpoint). Origin access: Origin access control → create new → let AWS update the bucket policy when prompted. Default root object: index.html. Skip WAF to avoid cost (choose "do not enable security protections" if offered).
  3. Wait for status Deployed (about 5 minutes). Open https://dxxxx.cloudfront.net. You have HTTPS for free.
  4. Try the raw S3 object URL in the browser: Access Denied. That is the point: only the CDN can read it.
  5. Edit index.html, re-upload, and reload. You may still see the old version (cache). Fix: Invalidations → Create → /*. Reload: new version.
  6. Optional (if you own a domain): create a Route 53 hosted zone and an Alias A record to the distribution. A domain costs about USD 12+/year and a hosted zone USD 0.50/month, so skip unless you want it.
  7. Cleanup: disable then delete the distribution; empty and delete the bucket.

5. Quiz

1. Which record type can point the root domain (example.com) to a CloudFront distribution?An Alias record (CNAMEs can't be at the root).
2. You want 10% of users to hit the new version of your app. Policy?Weighted.
3. Users in Europe should hit eu-west-1 and Asia users ap-southeast-1. Policy?Latency-based.
4. How do you let only CloudFront read a bucket?Origin Access Control and a bucket policy; keep Block Public Access on.
5. Content updated but users see old data. Quick fix?Create a CloudFront invalidation (or use versioned file names).
6. Which service routes traffic to a standby site when the primary fails?Route 53 failover routing with health checks.
