Route 53 and DNS: Names for Your Servers

By the end of today you can Explain how a browser turns a name into an IP, create DNS records, and choose a routing policy (simple, weighted, latency, failover).

1. First principles: computers want numbers, humans want names

Servers find each other by IP address. People remember google.com. DNS (Domain Name System) is the translation service, and Route 53 is AWS's DNS (port 53 is DNS's port).

Analogy: the phone bookYou look up "Mama Ngina's Bakery" and get a phone number. DNS looks up shop.example.com and returns 203.0.113.10. A hosted zone is your page in the phone book; each record is one entry.

2. Records you must know

TypeMapsExample
Aname → IPv4shop.example.com → 203.0.113.10
AAAAname → IPv6
CNAMEname → another name (not allowed at the root/apex)www → shop.example.com
Alias (Route 53 only)name → AWS resource (CloudFront, ALB, S3 site). Works at the apex, free queriesexample.com → d123.cloudfront.net
MX / TXTMail routing / verification text

TTL (time to live) is how long resolvers cache an answer. Low TTL = changes spread fast; high TTL = fewer lookups.

3. Routing policies (exam favourite)

PolicyReal-life use
SimpleOne answer. A single web server
WeightedSend 10% of users to a new version (canary release)
LatencySend each user to the Region that responds fastest
FailoverActive/passive: switch to a standby when the health check fails
GeolocationRoute by user's country (language, licensing)
GeoproximityRoute by distance, with a bias you can shift
MultivalueReturn up to 8 healthy IPs

4. Lab

CostsA hosted zone is about USD 0.50/month. A domain costs from ~USD 3 to 15+/year and is optional. If you don't want to buy a domain, do steps 4 to 6 only with a free domain you own, or read through and do the Day 11 CloudFront lab instead. Don't pay for something you'll abandon.
  1. Route 53 → Registered domains → Register a cheap domain (e.g. yourname-lab.click). It takes a few minutes. Alternatively skip to step 4 if you already own one.
  2. Hosted zones → your zone is created automatically.
  3. Start your Day 8 instance and note its public IP (it changes after a stop/start; an Elastic IP would keep it fixed).
  4. Create record: name app, type A, value = that IP, TTL 60, simple routing.
  5. Test from your terminal: 
    nslookup app.YOURDOMAIN.click
curl http://app.YOURDOMAIN.click
  6. Weighted demo (needs two instances or two IPs): create two A records both named canary, weights 90 and 10, with different Set IDs. Run nslookup repeatedly and watch the mix.
  7. Health check + failover: Route 53 → Health checks → create one on your IP, port 80, path /. Create a Primary failover record tied to it and a Secondary pointing elsewhere. Stop the instance, wait about 3 minutes, and watch DNS flip to the secondary.
  8. Cleanup: delete the records, health check and (if you are done) the hosted zone. Domain registration can be left to expire if you turn off auto-renew.

5. Exam notes

Remember
  • Route 53 = DNS + domain registrar + health checks. It is a global service with a 100% availability SLA.
  • Alias vs CNAME: alias works at the zone apex and for AWS targets; use it for CloudFront/ALB.
  • Latency = performance. Failover = DR. Weighted = testing/gradual rollout. Geolocation = compliance/localisation.

6. Quiz

Q1. Point example.com (apex) at a CloudFront distribution. Which record?Alias A record (CNAME isn't allowed at the apex).
Q2. Roll out a new app version to 5% of users first?Weighted routing.
Q3. Automatic switch to a standby site when primary is down?Failover routing with a health check.
Q4. Users in Europe must get EU-hosted content for legal reasons?Geolocation routing.
Q5. You changed a record but users still see the old IP. Why?Cached by resolvers until the TTL expires.
