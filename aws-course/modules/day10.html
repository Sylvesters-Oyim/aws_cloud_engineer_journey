DNS, Route 53 and CloudFront

By the end of today you can Explain how a domain name becomes an IP address, pick the right Route 53 routing policy, and serve a private S3 website fast and securely through CloudFront.

1. First principles: computers speak numbers, people speak names

Servers are found by IP address. Humans remember mybank.com. DNS (Domain Name System) is the phone book that converts one to the other. Route 53 is AWS's DNS service (53 is the DNS port).

Analogy: asking for directionsYour browser asks its ISP's resolver "where is shop.example.com?". The resolver asks the root ("who handles .com?"), then the .com servers ("who handles example.com?"), then finally your Route 53 zone, which answers "go to 203.0.113.10". The answer is remembered for a while (the TTL), like writing the address on a sticky note.

2. CloudFront: a pizza scooter on every street

CloudFront is a CDN (content delivery network). Copies of your files are cached at edge locations near users, so a visitor in Nairobi doesn't wait for a server in Virginia. It also gives you free HTTPS, DDoS protection (Shield Standard) and WAF integration.

The secure pattern: keep your S3 bucket private and let only CloudFront read it, using Origin Access Control (OAC). Nobody can bypass the cache and hit the bucket directly.

3. Lab: private S3 site behind CloudFront (45–60 min)

  1. S3 → create bucket (unique name, e.g. yourname-day10-site). Keep Block all public access ON.
  2. Upload an index.html (reuse your nginx-lab page or write <h1>Served by CloudFront</h1>).
  3. CloudFront → Create distribution. Origin: your S3 bucket. Under origin access choose Origin access control (recommended) → create new OAC. Set Default root object to index.html. Use the free/cheapest plan options offered, no WAF needed.
  4. When created, CloudFront shows a banner: Copy policy, then go to the bucket → Permissions → Bucket policy and paste it. This is what allows only CloudFront.
  5. Wait until the distribution status is Deployed (5–10 min, go make tea). Open https://dxxxx.cloudfront.net. 🎉
  6. Prove it's locked: try the bucket's own S3 URL, which must return Access Denied.
  7. Check headers from CloudShell: 
    curl -sI https://YOUR-ID.cloudfront.net | grep -i -E "x-cache|via"
# run it twice: 1st = "Miss from cloudfront", 2nd = "Hit from cloudfront"
  8. Optional DNS practice (free): dig +short google.com and dig +trace example.com from CloudShell/your Linux box to watch the hierarchy. A Route 53 hosted zone costs USD 0.50/month, but one deleted within 12 hours isn't charged: create a zone for a made-up domain, add an A record, view it, delete it.
  9. Cleanup: disable then delete the distribution, empty and delete the bucket.

4. Quiz

1. Which record type works at the zone apex and points to a CloudFront distribution?Alias record.
2. Send 5% of users to a new app version?Weighted routing.
3. Automatic failover to a standby site?Failover routing with a health check.
4. How do you stop people bypassing CloudFront and hitting S3 directly?Private bucket + Origin Access Control.
5. What is an edge location?A CloudFront/Route 53 site close to users that caches content.
