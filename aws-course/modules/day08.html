VPC: Your Private Network in the Cloud

By the end of today you can Explain what a VPC, subnet, route table and internet gateway are, tell a public subnet from a private one, and build your own VPC with a web server reachable from the internet.

1. First principles: why do we need a network of our own?

On Day 5 your EC2 instance "just worked" because AWS placed it in a default VPC. But real companies need control: which servers face the internet, which must stay hidden (databases), and who may talk to whom. A VPC (Virtual Private Cloud) is your own isolated network inside a Region, with an IP address range you choose.

Analogy: a gated estateThe VPC is the whole fenced estate. Subnets are streets inside it (each street sits in one Availability Zone). The internet gateway is the main gate to the public road. Route tables are the road signs on each street saying "to leave the estate, go through the main gate". A street with no sign to the gate is private: residents can talk to each other but strangers cannot drive in.

2. The five building blocks

PieceWhat it doesRemember
VPCYour isolated network, defined by a CIDR block such as 10.0.0.0/16Lives in one Region, spans all its AZs
SubnetA slice of the VPC range, e.g. 10.0.1.0/24Lives in exactly one AZ
Route tableRules that decide where traffic goesEach subnet uses one
Internet gateway (IGW)Door between VPC and the internetAttach to VPC, then add a route 0.0.0.0/0 → igw
Security groupVirtual firewall on the instanceStateful, allow rules only
The one-line definition of a public subnetA subnet is public if its route table has a route to an internet gateway. That's it. No route to the IGW = private.

CIDR in 60 seconds

10.0.0.0/16 means "the first 16 bits are fixed, the rest are mine to use". The bigger the number after the slash, the smaller the network.

CIDRAddressesUse
/1665,536Whole VPC (largest allowed)
/24256A typical subnet
/2816Smallest subnet allowed

AWS reserves 5 addresses in every subnet, so a /24 gives you 251 usable. Pick ranges that will not overlap with your office or other VPCs, because you may connect them later.

3. Lab: build it from scratch (about 45 min)

Cost safetyVPCs, subnets, route tables and IGWs are free. The only cost is the EC2 instance (use a free-tier-eligible type, e.g. t3.micro or t2.micro, as offered). We deliberately do not create a NAT Gateway today, because it bills hourly. Terminate the instance at the end.
  1. Create the VPC. Console → VPC → Your VPCs → Create VPC → "VPC only". Name lab-vpc, IPv4 CIDR 10.0.0.0/16. Create.
  2. Create two subnets (VPC → Subnets → Create): public-a = 10.0.1.0/24 in AZ eu-west-1a; private-b = 10.0.2.0/24 in AZ eu-west-1b. (Use your Region's AZ names.)
  3. Create and attach an internet gateway. Internet gateways → Create lab-igw → Actions → Attach to VPC → lab-vpc.
  4. Make the public route table. Route tables → Create public-rt in lab-vpc → Routes → Edit → add 0.0.0.0/0 target Internet Gateway lab-igw. Then Subnet associations → attach public-a only.
  5. Auto-assign public IPs. Select public-a → Actions → Edit subnet settings → tick Enable auto-assign public IPv4 address.
  6. Security group. EC2 → Security Groups → Create lab-web-sg in lab-vpc. Inbound: HTTP (80) from Anywhere, SSH (22) from My IP only.
  7. Launch an instance (Amazon Linux 2023) into lab-vpc / public-a with lab-web-sg. In Advanced → User data, paste: 
    #!/bin/bash
dnf install -y nginx
echo "<h1>Hello from my own VPC</h1>" > /usr/share/nginx/html/index.html
systemctl enable --now nginx
  8. Test. Open http://<public-IP> in your browser. You should see your heading.
  9. Break it on purpose (this is where learning happens): remove the 0.0.0.0/0 route from public-rt, refresh the page (it hangs), then add the route back. You just proved that routing, not the instance, decides if a subnet is public.
  10. Cleanup: terminate the instance. Then delete (in this order): security group, subnets, detach and delete the IGW, route table, VPC. The VPC wizard's "Delete" on the VPC also removes most attached pieces.

4. Why not just use the default VPC?

The default VPC is a ready-made public network meant for quick starts. Production uses custom VPCs so databases and internal services sit in private subnets. Next module we add the missing piece: how a private server reaches the internet for updates without being reachable from it (NAT).

5. Exam notes

Remember
  • VPC = Region-wide; subnet = one AZ. For high availability, create subnets in at least 2 AZs.
  • Public subnet = route to an Internet Gateway. An instance also needs a public/Elastic IP to be reachable.
  • Each subnet reserves 5 IPs. Smallest subnet /28, largest VPC /16.
  • Every VPC gets a default route table with a local route you cannot delete.
  • One VPC can have only one internet gateway attached; one IGW attaches to only one VPC.

6. Quiz

1. What makes a subnet "public"?A route in its route table sending 0.0.0.0/0 to an internet gateway.
2. A subnet can span multiple Availability Zones. True or false?False. One subnet = one AZ. A VPC spans all AZs in the Region.
3. How many usable IPs in a /24 subnet?251 (256 minus 5 reserved by AWS).
4. Your instance is in a public subnet but the website times out. Name two things to check.Security group allows port 80; instance has a public IP; route table has the IGW route; IGW is attached.
5. Which AWS component is the door between your VPC and the internet?Internet gateway.
6. Why choose 10.0.0.0/16 carefully?Overlapping CIDRs cannot be peered or connected to on-premises networks later.
